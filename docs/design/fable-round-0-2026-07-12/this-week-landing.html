This Week: the landing that answers "what changed" and "who do I call"

The current build greets the analyst with four aggregations that disagree and alerts that all say "Critical Severity 100% · 16m ago." This surface replaces all of it with three bands in the order the analyst thinks: a delta feed of named events, a queue with its arithmetic shown, and one quiet portfolio pulse. Question three ("what do I say") lives in the case file, one click away.

01 · Laws of the landing

Inherits everything upstream. Adds six.

W1
Time is anchored to the pipeline and the analyst, never the clock.
"16m ago" is banned; the data is weekly. Every timestamp is one of two kinds: the pipeline run vintage ("run Jul 6, 06:00") or the analyst's own anchor ("since your last review, Mon Jun 29"). The whole page is a diff between those two points.
W2
No event without a named trigger.
Every feed entry follows one grammar: subject, verb, evidence, consequence. "200 East 42nd St. entered Critical: Δ '24 arrived at −66%, completing the third condition." An alert that can't say what tripped it doesn't render.
W3
One aggregation, and it agrees with the queue.
The portfolio pulse is the only summary on the page, computed from the same tier fields the queue filters on, and rendered visually subordinate. The four-disagreeing-summaries problem is solved by deletion, not reconciliation.
W4
The queue does its arithmetic in public.
"23 Critical − 6 contacted − 2 dismissed = 15 to review." The first number the analyst acts on is derived on the surface, from the Critical definition plus workflow state. No unexplained counts anywhere on the page.
W5
The week carries over.
Workflow state persists, so the landing distinguishes new this week from carried from last week. Monday never starts from zero, and nothing silently disappears because a score moved.
W6
Buttons first, command bar second.
The known Monday questions are one-click filter buttons routed through the existing /api/query FilterSpec path with canned prompts. ⌘K is the power path for everything else, not the front door. A weekly-cadence user gets conventions, not shortcuts to memorize.

1

Top bar

The week anchor states both time points the page diffs between (W1). The one orange sits on Compose weekly digest, the primary weekly action and ConEd's second explicit ask. The command bar is present but visually second to buttons and filters (W6).

2

Delta feed

Six event kinds, one grammar, each with evidence and a next step. The DATA event matters most for honesty: when a vintage batch lands, the analyst sees coverage move (35% to 45%) and how many tier changes resulted, instead of 118 identical alerts.

3

Queue arithmetic

The 15 the analyst starts with is derived in public (W4) from the Critical definition plus workflow state. Filter chips are the Monday questions as buttons, each a canned FilterSpec through the existing /api/query path. "Carried · wk 3" makes aging visible: a building sitting unreviewed for three weeks is its own signal.

4

Queue rows are Spec 1 cells

The score cell arrives unchanged, plus a one-line top driver in real units so the analyst can triage without opening the case file. Row click goes straight to the case file; there is no intermediate modal.

5

Portfolio pulse

One stacked bar, week-over-week deltas, coverage, and vintages, in the quietest treatment on the page (W3). This is also the leadership-demo view in miniature: when David screen-shares, the pulse answers the portfolio question without a separate executive dashboard.

The empty state, for completeness:

Nothing crossed a threshold since your last review.
Pipeline ran Jul 6, 06:00 · 1,210 buildings scanned · your queue carries over: 9 in review · 2 awaiting report

A quiet week is a real result, stated with the same evidence grammar. No sparkle emoji, no apology, and the carry-over counts keep it actionable.

03 · Event grammar

Six kinds, one sentence shape

TIER ↑ / ↓A building entered or left a tier or the Critical state. Evidence names which condition changed, not just the new label. Leaving via outreach cites the contact and the cooling-off window.
PERMITA DOB filing appeared for a tracked building. Evidence: filing date and type. Consequence framing may cite the cluster ("permit-driven churn is this cluster's signature"), which is exactly the lens David asked the tool to lead with.
DATAA vintage batch arrived or coverage moved. Always aggregated to one line with the count and the coverage shift; a data drop is one event, never 118.
STATUSA workflow-state change by an analyst. Evidence: who, when. Confirmed and False positive events note that they become training labels, which keeps the feedback loop visible.
DIVERGEThe ML rank and rule tier newly disagree for a building (the ◇ state from Spec 1). Fires only on becoming divergent, not while remaining so.
MODELReserved for Phase 2: a model version change or validation update ("GBM v2 deployed · back-test 74% against ConEd disconnect records"). Rare, loud, and worth a line at the top of the feed when it happens.
04 · Open questions before this ships
  • Snapshot diffing is new pipeline scope. Events require keeping run N−1 and diffing against run N (tiers, Critical membership, permits, coverage). Cleanest home is the end of Ismael's pipeline, emitting an events.json the API serves; the alternative (diff at API boot) couples the server to two data generations. Decide with Ismael before anything here is buildable.
  • "Your last review" needs a marker. Per-analyst session anchoring rides on the write path from Spec 2: a last-reviewed timestamp per actor. With shared-token auth there is exactly one "you" for now, which is honest to ship, but the copy should not pretend otherwise when a second analyst appears.
  • Cooling-off window length. Contacted suppresses re-queueing for how long? Two weeks, four, until next vintage? This is a David question and belongs in the same sync as digest cadence and format.
  • Event retention. Does the feed show one week or scroll back through history? Recommendation: the landing shows since-last-review only, with a full event log living on the case-file timeline, which this spec deliberately leaves to the case-file body.
  • Divergence event volume. If the S2 population turns out large (flagged in Spec 1), DIVERGE events need batching like DATA events. Same unknown, same owner: Ismael.
