## The 5 panel-review findings

### 4. `validateModelMeta` allowlist with `safeStr` / `safeNum` ✓

`api/server.js:590-608`. Explicit key list, no `...spread`. `safeStr` bounds string length (default 128, 512 for `label_definition`), rejects empties. `safeNum` rejects `Infinity` / `NaN` via `isFinite`. Prevents:
- Arbitrary JSON keys reaching API responses (data leakage via added keys)
- XSS payloads in string fields (bounded length + surface is JSON, not HTML — but defense-in-depth for future FAQ interpolation)
- Renderer-corruption via `Infinity%` if a bad cv_auc slipped through

Solid pattern. Small nit: the catch-block fallback object at :623 is not run through `validateModelMeta`, but since it's a hardcoded literal there's no attack surface. Consistent-behavior argument would say route it through anyway, but not a blocker.

### 5. `_modelMetaLoadedAt = now` in `finally` block ✓

`api/server.js:625-632`. The concern was: if `readFileSync` throws on transient corruption, without a `finally` block the timestamp stays stale and every subsequent request re-attempts the sync read (unbounded I/O). With `finally`, the failed load still updates the timestamp, so the TTL rate-limits retries. Correct.

Small note: the try block also sets `_modelMetaLoadedAt = now` inside a successful read, so on the happy path the assignment runs twice. Harmless. Removing the redundant assignment in try would be a nit-level cleanup.

### 6. `/api/meta` gets `requireAuth` ✓

`api/server.js:637`. Changed from `app.get("/api/meta", (_req, res) => ...)` to `app.get("/api/meta", requireAuth, ...)`. Rationale (unauth cache-TTL probing → retrain-cadence side channel) is defensible — a public endpoint that returns `run_date` and `model_version` leaks pipeline cadence to unauthenticated scrapers.

### O4. `validated` boolean logic tolerates non-canonical values

`api/server.js:927`: `const validated = (m.validation_status ?? "unvalidated") !== "unvalidated";`

Any string other than `"unvalidated"` renders "back-tested" — including `""`, `"validating"`, `"UNVALIDATED"` (case mismatch), typos. `validateModelMeta` sets fallback `"unvalidated"` on empty strings via `safeStr`, so in-band the value is bounded. But the logic is loose defense.

Tighter form: `const validated = m.validation_status === "validated" || m.validation_status === "back-tested";`

Not a blocker. Flag for future strengthening once the spec pins the exact validation_status vocabulary (currently: "unvalidated" defined, "back-tested" implied by §4.4 but not canonically listed).
