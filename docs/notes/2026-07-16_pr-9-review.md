## Alignment issues

### 1. Boundary violation on frontend (flagged in PROJECT_STATE current-risk #1)

W-law changes land on `src/components/RiskTable.jsx` and `src/components/BuildingPanel.jsx`, which R4 (Pedro's score cell) and R5 (Pedro's case-file header) are scheduled to **replace**. R1 (Pedro's legacy separation) hasn't shipped.

Two failure modes:
- **Merge PR #9 first → R1 runs later:** all this workflow logic gets copied into `src/legacy/` and frozen. New build has no contact/dismiss/QuickFilters. R9 (Pedro's queue) reimplements W4 subtraction from scratch.
- **Merge R1 first:** PR #9 must be rebased against the new layout, and Ismael has to pick which side of the split these features land on.

Workflow features probably belong in the *new* build. Their natural home is after R4/R9 (Pedro's queue), authored against new-build components — not against files scheduled for freeze.

### 2. FAQ copy needs Edwin's bless-or-tweak (not a rewrite)

The rewritten ml_risk FAQ answer at `server.js:976`:

> "The attrition risk score (ml_risk) is an XGBoost classifier prediction (0–1) that ranks a building's likelihood of significant steam demand decline relative to peers. It ranks a true churner above a non-churner about ${Math.round((getModelMeta().cv_auc ?? 0.68) * 100)}% of the time (${getModelMeta().cv_kfold ?? 5}-fold CV, ${getModelMeta().n_positive ?? 54} positive labels). Key drivers include LL97 penalty exposure, steam GHG share, Energy Star score, and peer attrition rates in the same cluster."

Assessment:
- **AUC no longer fabricated** given R3's 0.6833 shipping in the same PR. The `?? 0.68` fallback renders ~identically to the real value; strictly speaking the fallback should probably render an explicit "unvalidated" or throw rather than silently returning a plausible number, but this is a defensive-coding nit, not a spec violation.
- **AUC interpretation sentence** matches the system-v1.1.md §7 rule 8 template shape ("ranks a true churner above a non-churner about X% of the time, K-fold CV, N positive labels"). Land the number, land the template.
- **"Likelihood… relative to peers"** — reads as rank/percentile language qualified by "relative to peers." Not probability-of-decline. Weaker than R2's L1-removal ambition but not the raw calibration claim the old copy had ("how likely… within the next cycle").
- **Edwin still owns the copy per R2 scope split.** The right move is a fast copy pass — bless, tweak the fallback behavior, or trim "likelihood" — not a rewrite.

### 3. R2 co-ownership: Edwin owes a copy pass

R2 scope explicitly splits into `Ismael: object + wiring; Edwin: rewritten chatbot answer copy`. Ismael did both; Edwin should sign off on the exact string before merge. Fast turnaround: an hour of work, not a blocker.

### 4. Scope-per-PR convention violated

CLAUDE.md §Git conventions says *"One PR per milestone where possible."* PR #9 lands R2 + R3 + R7 (partial) + W-laws frontend under one W-laws-titled PR. Reviewers can't accept/reject per milestone; can't cherry-pick R7 (ready) or R2+R3 (ready pending Edwin copy) while holding W-laws frontend (boundary risk).

Not a hard blocker — the mixed content can still merge if we treat it as a bundle and accept the review overhead. But splitting makes the R1 rebase for the frontend piece cleaner.

## What's genuinely good and should survive

- **`api/db.js`** — clean, well-scoped. CHECK constraint tied to a JS `Set` so schema and code can't drift, append-only pattern, composite index supports the `DISTINCT ON` bulk query. Solid R7 backbone.
- **Status endpoint design** — bulk route registered before `:bbl` to prevent param shadowing (explicitly commented); BBL regex validation; actor pseudonymized via SHA-256 of session token so raw tokens never touch the DB; note sanitization strips bidi controls. Careful work.
- **Login length-oracle fix** — hashing both sides before `timingSafeEqual` prevents a timing-side-channel on password length. Non-obvious, worth keeping.
- **`api/db.js` `initSchema` idempotence** — `CREATE TABLE IF NOT EXISTS` + `CREATE INDEX IF NOT EXISTS` so repeat container starts don't fail.
- **`trust proxy` widening** — expands from `NODE_ENV === "production"` to `DATABASE_URL || NODE_ENV === "production"`; catches Railway preview environments.
- **BuildingPanel duplicate declarations removal** — real bug fix that would break under Vite 8's stricter parsing.
- **URL.revokeObjectURL race fix** — 10s deferred cleanup; small win.
